# Инструмент для проверки Markdown-документов

Этот инструмент автоматизирует проверку и улучшение Markdown-документов с помощью нескольких больших языковых моделей через Cursor CLI (`cursor-agent`).

## Как это работает

1. **Параллельная проверка**: Несколько рецензентов (LLM) одновременно проверяют документ по контрольному списку критериев
2. **Агрегация замечаний**: Отдельная модель объединяет все замечания, удаляет дубликаты и противоречия
3. **Автоматическое исправление**: Агрегатор редактирует документ, исправляя найденные проблемы
4. **Итерации**: Процесс повторяется до тех пор, пока все рецензенты не одобрят документ (или не будет достигнуто максимальное число итераций)

## Предварительные требования

### 1. Установка Python

Убедитесь, что Python 3.8+ установлен:

```powershell
python --version
```

### 2. Установка Cursor CLI

Установите `cursor-agent` CLI в Windows PowerShell:

```powershell
irm 'https://cursor.com/install?win32=true' | iex
```

Для других операционных систем:

```bash
# macOS, Linux, WSL
curl https://cursor.com/install -fsS | bash
```

### 3. Аутентификация в Cursor

После установки войдите в свой аккаунт Cursor:

```powershell
cursor-agent
```

При первом запуске вас попросят войти в систему. Следуйте инструкциям в терминале.

Альтернативно, можно использовать API-ключ:

```powershell
# Установить ключ через переменную окружения
$env:CURSOR_API_KEY = "ваш-api-ключ"
```

## Использование

### Базовое использование

Запустите проверку документа:

```powershell
python tools/md-review/review.py path/to/document.md
```

### С пользовательским конфигом

```powershell
python tools/md-review/review.py path/to/document.md --config path/to/custom-config.json
```

### Примеры

```powershell
# Проверить README
python tools/md-review/review.py README.md

# Проверить документацию
python tools/md-review/review.py docs/AGENT_NAV.md
```

## Конфигурация

Файл `config.json` содержит все настройки инструмента:

```json
{
  "num_reviewers": 2,
  "reviewer_models": [
    "auto",
    "auto"
  ],
  "aggregator_model": "auto",
  "max_iterations": 1,
  "checklist_path": "checklist.md",
  "log_directory": ".review-logs"
}
```

### Параметры конфигурации

- **`num_reviewers`** (число): Количество параллельных рецензентов (по умолчанию: 2)
- **`reviewer_models`** (массив строк): Модели для каждого рецензента. Доступные значения:
  - `"auto"` — автоматический выбор модели Cursor
  - Конкретная модель, например `"claude-sonnet-4"`
- **`aggregator_model`** (строка): Модель для агрегатора (рекомендуется `"auto"`)
- **`max_iterations`** (число): Максимальное число итераций проверки (по умолчанию: 1)
- **`checklist_path`** (строка): Путь к файлу с контрольным списком относительно папки инструмента
- **`log_directory`** (строка): Папка для сохранения логов проверки (игнорируется git)

### Изменение конфигурации

#### Увеличить число рецензентов

Отредактируйте `config.json`:

```json
{
  "num_reviewers": 4,
  "reviewer_models": [
    "auto",
    "auto",
    "auto",
    "auto"
  ]
}
```

#### Использовать конкретные модели

```json
{
  "reviewer_models": [
    "claude-sonnet-4",
    "gpt-4o"
  ]
}
```

Список доступных моделей можно получить командой:

```powershell
cursor-agent --list-models
```

#### Увеличить число итераций

```json
{
  "max_iterations": 3
}
```

## Контрольный список критериев

Файл `checklist.md` содержит критерии, по которым рецензенты оценивают документ. Вы можете редактировать этот файл, добавляя или удаляя пункты проверки в зависимости от ваших требований.

Разделы по умолчанию:
- Структура и организация
- Качество контента
- Форматирование и стиль
- Язык и грамматика
- Лучшие практики Markdown

## Логи проверки

Каждый запуск инструмента создаёт папку с логами:

```
tools/md-review/.review-logs/YYYYMMDD_HHMMSS/
├── review.log                          # Основной лог
├── iteration_1_reviewer_0_auto.txt     # Вывод рецензента 0
├── iteration_1_reviewer_1_auto.txt     # Вывод рецензента 1
├── iteration_1_reviews.json            # Объединённые результаты проверки
└── iteration_1_aggregator.txt          # Вывод агрегатора
```

Логи помогают понять, какие замечания были сделаны и какие исправления применены.

## Интеграция с Git (опционально)

### Post-commit хук

Если вы хотите автоматически проверять Markdown-файлы после коммита, создайте файл `.git/hooks/post-commit`:

```bash
#!/bin/bash
# Проверить изменённые .md файлы
changed_md=$(git diff-tree -r --name-only --no-commit-id HEAD | grep '\.md$')

if [ -n "$changed_md" ]; then
  echo "Running markdown review..."
  for file in $changed_md; do
    if [ -f "$file" ]; then
      python tools/md-review/review.py "$file"
    fi
  done
fi
```

Сделайте его исполняемым:

```bash
chmod +x .git/hooks/post-commit
```

**Примечание**: Этот инструмент **не включает хуки автоматически**. Включайте их только если уверены, что хотите проверять каждый коммит.

### Cursor хук (опционально)

Добавьте в `.cursor/hooks.json`:

```json
{
  "afterCommit": {
    "enabled": false,
    "command": "python tools/md-review/review.py ${changedFiles.md}"
  }
}
```

Установите `"enabled": true`, чтобы активировать.

## Устранение неполадок

### `cursor-agent: команда не найдена`

Убедитесь, что Cursor CLI установлен и добавлен в PATH:

```powershell
# Проверьте установку
cursor-agent --version

# Если не работает, переустановите
irm 'https://cursor.com/install?win32=true' | iex
```

### Таймаут при запросах к моделям

Увеличьте таймаут в скрипте `review.py`, изменив параметр `timeout` в методе `_run_cursor_agent`:

```python
timeout=600,  # 10 минут вместо 5
```

### Модели не возвращают валидный JSON

Инструмент автоматически повторяет запрос один раз. Если проблема сохраняется:
1. Проверьте логи в папке `.review-logs/`
2. Убедитесь, что используемые модели поддерживают структурированный вывод
3. Попробуйте использовать модель `"auto"`

### Агрегатор не вносит изменения

Убедитесь, что в выводе агрегатора есть подтверждение применённых изменений. Если изменения не применились:
1. Проверьте, что файл доступен для записи
2. Проверьте логи агрегатора в `.review-logs/`
3. Попробуйте запустить с более мощной моделью

## Рекомендации

1. **Начните с настроек по умолчанию** — 2 рецензента с моделью `auto` хорошо работают для большинства случаев
2. **Постепенно увеличивайте итерации** — `max_iterations: 1` достаточно для простых документов
3. **Проверяйте логи** — они помогут понять, что именно было исправлено
4. **Редактируйте checklist.md** — адаптируйте критерии под ваши требования
5. **Используйте version control** — коммитьте документ до проверки, чтобы можно было откатить изменения

## Ограничения

- Инструмент использует ваш аккаунт Cursor и его квоты на запросы к моделям
- Большие документы могут требовать длительного времени обработки
- Качество проверки зависит от выбранных моделей и контрольного списка
- Автоматические исправления могут требовать ручной доработки
